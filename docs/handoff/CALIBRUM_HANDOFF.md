## PART 4 — THE MODEL CONTRACT (binding interface)

Every scoring surface in every app you build MUST consume `05_model/mrs_v0/mrs_model.json` rather than inventing its own scoring logic, so demos and the real model can never drift apart. Schema: `{ kind: "logistic_scorecard_v0", event: string, features: string[43], mean: {feature: number}, std: {feature: number}, coef: {feature: number}, intercept: number, score_scaling: { PDO: 40, base_score: 600, base_odds: 15, clip: [300, 850] }, holdout_metrics: {...} }`. Scoring procedure: z = (x − mean)/std per feature; logit = intercept + Σ coef·z; p = 1/(1+e^−logit); odds_good = (1−p)/p; MRS = clip(base_score + (PDO/ln 2)·ln(odds_good/base_odds), 300, 850). Financial mapping (illustrative, documented, monotone — label as such in every UI): premium_rate = 9.0% − MRS/1000 × 7.5% of asset value per year; max LTV = 25% + MRS/1000 × 55%; credit spread = (1200 − MRS) bps over SOFR; residual value = 30% + MRS/1000 × 40% of cost. When a surface needs a demo machine, generate its feature vector and push it through this exact contract.
